# rh-parity: replay legacy captures through the Rust core

The differential harness and the project's main oracle. It loads captured scenarios from the legacy TypeScript game
(`parity/fixtures/*.json`, format `rh-legacy-scenario/1`), replays each through `rh_sim::Sim`, and compares every tick.
Tolerances and their reasons are in [parity/README.md](../../parity/README.md). Every fixture struct denies unknown keys,
so a field the capture tool starts emitting fails loudly instead of being ignored.

## Where it sits

It calls `rh-sim` only. The captures it reads are generated by `parity/legacy-capture/capture.ts` and the
`tools/<area>-fixtures/capture.sh` scripts; they are never hand-edited.

## Entry points

- `src/lib.rs`: the fixture types, the projection table that maps legacy keys to Rust state, and the comparison.
- `src/bin/parity_report.rs`: `parity-report`, a readable report of mismatches
  (`tick <t> <id>: <field> <rust> vs legacy <legacy>`).
- `src/bin/parity_bench.rs`: `parity-bench`, timing over the captures.
- `src/bin/status_probes.rs`: `status-probes` (needs `--features trusted-status-probes`).
- `src/bin/hitbox_fixtures.rs`, `frost_wall_aim_fixtures.rs`, `frost_wall_walk_fixtures.rs`: fixture writers for their
  mechanics.
- `src/combat.rs`, `frost.rs`, `holy.rs`, `plague.rs`, `sentenced.rs`, `vision.rs`, `hunt.rs`, `fire_roam.rs`: the
  per-mechanic comparisons. `tests/` has one file per mechanic.

## Run and test

```sh
cargo test -p rh-parity
cargo run -p rh-parity --bin parity-report
```

## Rules

Local rules: [AGENTS.md](AGENTS.md). Never refresh a capture, loosen a tolerance or edit a fixture to make a test pass;
a deliberate difference from legacy is recorded in `docs/DEVIATIONS.md` and compared through that entry.
