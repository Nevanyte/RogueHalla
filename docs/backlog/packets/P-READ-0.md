## The tool

`python3 scripts/readability_check.py [--root DIR] [--allowlist FILE] [--write-allowlist]`

- Lists files with `git ls-files` under `--root` (default: the repository root of the script), so build output and
  untracked files never count. Allowlist default: `<root>/scripts/readability-allowlist.txt`.
- Applies the four rules of `docs/agent/READABILITY.md` exactly as its table states (paths, limits, which files are
  tests, the excluded synced copy `client-unity/UnityProject/Assets/RoguehallaNet/**`). Line count = number of lines in
  the file (`wc -l` semantics; a final line without a newline still counts).
- Rust header: the first line that is not blank starts with `//!`. C# summary: a line whose stripped text starts with
  `/// <summary>` appears before the first line matching a type declaration
  (`(public|internal|private|protected|sealed|static|abstract|partial|\s)*(class|struct|interface|enum|record)\s`).
- Allowlist grammar (`#` comments and blank lines ignored; fields split on whitespace; reasons run to end of line):
  `size <path> <max>`, `header <path>`, `readme <dir>`, `frozen <path> <reason>`, `exempt <glob> <reason>`
  (`**` matches across directories). `exempt` removes matching files from the size rule only.
- **Fails (exit 1)** on, each printed as `<rule> <path>: <message>`:
  1. a violation with no matching entry;
  2. a `size` entry whose file is now over its recorded `<max>` ("grew");
  3. a stale entry: `size` for a file now within the limit, `header` for a file that has one, `readme` for a directory
     that has one ("remove this entry");
  4. any entry naming a path that does not exist (this is what stops a `frozen` file being moved or renamed), and an
     `exempt` glob that matches no file;
  5. a duplicate entry, a malformed line, an unknown kind, a `frozen`/`exempt` line without a reason.
- **Passes (exit 0)** otherwise. Last line either way:
  `readability: OK (allowlisted: <a> over size, <b> without header, <c> without README; <f> frozen, <e> exempt)` or
  `readability: FAIL (<n> problems)`.
- `--write-allowlist` prints to stdout a complete allowlist for the current tree: every current violation as a
  `size`/`header`/`readme` line (sorted by kind, then path), and every `frozen` and `exempt` line of the existing
  allowlist kept with its reason. It exits 0 and checks nothing. Coordinator seeding only.
- Python 3 standard library only; runs in under two seconds on this repository.

## Seeding the allowlist (implementer)

1. `exempt` lines, reasons as given:
   - `crates/rh-policy/src/bots/temporal_percept/**` dormant legacy Brain, not activated; ported line by line
   - `crates/rh-protocol/src/samples.rs` golden-vector table, one long list by design
   - `client-unity/UnityProject/Assets/Scripts/**/BakedContent.cs` generated by the content bake
     (adjust the glob to where `BakedContent.cs` actually lives; it must match it)
2. `frozen` lines, one per source file under `crates/` or `client-unity/` that another tool names by path, with the
   naming tool as the reason:
   - files in the `FILES=` (or equivalent) lists of `tools/*/run-mutants.sh` and `tools/*/run-mutants.py`, and in the
     `---`/`+++` headers of `tools/*/mutants/*.patch` (about 58 files; reason `named by tools/<dir>/<file>`);
   - `crates/rh-placement/src/service/{mod,run}.rs` and `crates/rh-placement/src/ledger/{mod,postgres,memory}.rs`
     (reason `path list in crates/rh-placement/tests/crash_restart.rs`);
   - the C# files `scripts/gate.sh` names by file name (`SrgbMeshColors`, `WeaponRangePresenter`, `HitZonePresenter`,
     `CampPatienceOutlines`; reason `named by scripts/gate.sh`).
   A file that only matches a pattern of a tool (not by its exact path) is not frozen. List in the hand-off any path a
   tool names that does not exist today (do not add it).
3. Then `--write-allowlist` for the rest, and commit the result. The check must pass on the branch.

## Gate step

One step, "readability (scripts/readability_check.py)", in both quick and full modes, always run (it is cheap), placed
with the other offline checks. On failure, the hint says: fix what the line names, or, if the work removed a violation,
delete that allowlist line; never add `size`/`header`/`readme` lines for new code. `gate.test.sh` gets a test that the
step is selected in quick and full mode.
