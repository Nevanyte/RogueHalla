## Behaviour to preserve
Commands are untrusted intent, decoded strictly and validated by Rust. Quest interactions expose only server-offered action tuples; private spell inventory, pending rewards and drops are owner-scoped. Bargain target indexes are `0..48` inclusive, as specified by the playtest plan. Existing quest view fields and legacy protocol fixtures remain unchanged.

## Acceptance checks
Rust/C#/JS v19 golden vectors round-trip. Invalid action/target combinations, oversized collections, duplicate drop indexes, invalid reward codes, non-finite times/positions, and action tuples without a matching quest row are rejected. Wire command 19 round-trips. InputSender queues a command using the public API. Existing legacy golden vectors remain unchanged.

## Known traps

The coordinator regenerates the v19 vectors with `cargo run --locked -p rh-protocol --bin protocol-fixtures`, the archetype identity with `cargo run --locked -p rh-parity --bin hitbox-fixtures`, and the derived native ability hash tape with `cargo test --locked -p rh-sim --lib record_ability_hash_tape -- --ignored`. The original source-capture fixtures stay frozen. As with P-FROST-WALL-2a, the full coordinator gate verifies the generated tape. The separate packet-oracle gate checks the board oracle first and then reports the tape's parity path.

The original gameplay cases and frozen pins remain intact.
